# Onboarding Test Scenarios for Personalization and Linguistic Variation

## Overview

This document describes the test scenarios to verify:
1. Personalization of the Free Analysis Result step (FreeAnalysisResultStep.tsx)
2. Linguistic variation in the legal explanations presented in the Free Analysis Result step
3. Correct operation of the onboarding flow, including payment simulation

The test scenarios are generated by the script `onboarding-test-scenarios.ts` and cover combinations of:
- Situations: `multa_transito`, `conversao_advertencia`, `suspensao_cnh`
- Process stages: `primeira_notificacao`, `recurso_jari`, `defesa_negada`
- Infraction categories: `excesso_velocidade`, `lei_seca`, `celular`, `vermelho`, `estacionamento`, `cnh_suspensao`, `outro`

## Prerequisites

1. The DefesAi application must be running locally or deployed to a test environment.
2. You have access to the onboarding flow (starts at `/` or `/onboarding`).
3. For payment simulation, the backend simulation endpoints must be active.

## Using the Test Fill Button

In the **Specific Infraction Data Step** (step 4 of onboarding), there is a "Test Fill Button" (labeled "Preencher Dados de Teste" or similar) that, when clicked, fills the form with randomly generated data for the currently selected infraction category.

To test a specific scenario:
1. Navigate to the onboarding flow.
2. Complete steps 1-3 (Service, Defense Stage, Infraction Identification) to reach step 4.
3. In step 4, select the infraction category matching your test scenario.
4. Click the "Test Fill Button" to populate the form with random data.
5. You can manually adjust the fields to match the exact values from a test scenario (if desired).
6. Proceed to the Free Analysis Result step (step 6) via the analysis processing step (step 5).

## Verifying Personalization

In the Free Analysis Result step (step 6), verify the following elements are personalized:

1. **Header**: Should show `Diagnóstico de [FirstName]` where [FirstName] is the first part of the lead name.
   - Example: If lead name is "Ana Maria Silva", header shows "Diagnóstico de Ana".

2. **Subtitle**: Should show the AIT number and vehicle plate.
   - Example: `Auto nº 1234567890 • Placa ABC1D23`

3. **Lead Phone**: If provided, should appear in the subtitle after the plate.
   - Example: `... • WhatsApp: (11) 99999-9999`

4. **Impact Section**: 
   - The fine amount should be shown as "R$ [amount]" in the impact estimate column.
   - The points should be shown as "[points] Pontos na CNH" in the same column.

## Verifying Linguistic Variation

The legal explanations in the Free Analysis Result step now have multiple variations for each argument type (ARG-001, ARG-051, ARG-002). To verify linguistic variation:

1. Go through the onboarding flow for a given scenario and reach the Free Analysis Result step.
2. Observe the exact wording of the explanations presented (typically 3 arguments are shown).
3. Go back to the previous step (using the browser back button or navigating through the wizard) and then return to the Free Analysis Result step (by re-running the analysis).
4. Observe that the wording of the explanations has changed (while maintaining the same legal meaning and structure).
5. Repeat this process multiple times to see different variations.

Note: The variation is random, so you may see the same variation twice in a row, but over multiple runs you should observe different wordings.

## Payment Simulation Verification

After reviewing the free analysis result, you can proceed to generate the full defense document by clicking "Gerar Minha Defesa". This will lead to:

1. **Required Data Step** (step 7): Verify that your personal information is pre-filled.
2. **Document Review Step** (step 8): Review the generated document.
3. **Document Checkout Step** (step 9): Here you can test payment simulation.

To test payment simulation:
- Choose either PIX or Credit Card as payment method.
- For PIX: The system will generate a QR code and a copia e cola code. You can simulate payment by clicking the "Confirmar Pagamento & Emitir Defesa" button (which calls the simulation endpoint).
- For Credit Card: Use the test card number `4242 4242 4242 4242` with any future date and any 3-digit CVV to simulate a successful payment.

After successful payment, you should be redirected to the case detail page showing the generated document.

## Notes

- The test fill button in SpecificInfractionDataStep generates random data each time it is clicked. For consistent testing, you may want to manually enter the values from a specific scenario.
- The linguistic variation is implemented by having multiple pre-defined explanations for each argument type and selecting one at random each time the FreeAnalysisResultStep component renders.
- The payment simulation uses backend endpoints that simulate successful payment without charging real money.
- For the best testing experience, clear your browser cookies or use an incognito window to start with a clean onboarding flow.

## Troubleshooting

- If personalization is not showing, check that the lead name, AIT number, plate, and phone are correctly set in the wizard state.
- If linguistic variation is not observed, try multiple runs and ensure you are not caching the component state (a hard refresh may help).
- If payment simulation fails, check the browser console for errors and ensure the backend is running.
